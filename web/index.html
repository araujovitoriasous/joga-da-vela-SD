Jogo da velha distribuído

Três programas Java. O servidor de match pareia dois jogadores por RMI. A partida segue por socket TCP. Cada jogada também sai por multicast para quantos displays estiverem ouvindo o mesmo grupo.

Arquitetura

Jogador A  --RMI getOponent-->  Servidor de match  <--RMI--  Jogador B
    |                                                            |
    +---------------------- TCP (uma jogada por linha) ----------+
    |                                                            |
    +-------- UDP multicast 225.1.1.NN:88NN ------->  Display(s)

O servidor fica em uma das VMs (152.92.236.14, .16 ou .17), junto com o RMIRegistry na porta 98NN. NN é o número da conta, de 00 a 99. Os displays usam o grupo 225.1.1.NN e a porta 88NN.

Como compilar

Precisa de Java 17 ou mais novo. Na raiz do projeto:

sh compilar.sh

Como executar

Troque 7 pelo seu NN e os IPs pelos das VMs. O mesmo NN nos três módulos.

# VM do match
java -cp bin velha.match.Principal --nn 7 --ip 152.92.236.14

# qualquer VM, quantos quiser
java -cp bin velha.display.Principal --nn 7

# dois jogadores, em máquinas diferentes
java -cp bin velha.jogador.Principal --nn 7 --rmi-host 152.92.236.14 --ip 152.92.236.16
java -cp bin velha.jogador.Principal --nn 7 --rmi-host 152.92.236.14 --ip 152.92.236.17

Para testar os dois jogadores na mesma máquina, omita --ip (cai em 127.0.0.1) e use --rmi-host 127.0.0.1. --porta fixa a porta TCP anunciada ao match, se a VM filtrar portas altas.

Conferência automática, sem humano:

java -cp bin velha.teste.TestePartida

Match

Um método remoto, nome do enunciado:

String getOponent(String jsonIn)

Pedido e resposta:

{"ip":"152.92.236.16","porta":50231,"protocolo":"tcp"}
{"ip":"152.92.236.17","porta":49811,"inicia":true}

O JSON é uma String. Cada chamada RMI chega numa thread. O primeiro jogador de um protocolo fica em wait dentro de getOponent. O segundo acha esse pedido na fila, preenche a resposta dos dois e faz notifyAll. Os dois return saem juntos e a fila esvazia o par. TCP só pareia com TCP.

Quem recebe inicia: true é X, abre o TCP e joga primeiro. Quem recebe false é O e dá accept no socket que já estava escutando antes do RMI. Se ninguém aparecer em 120 segundos, a chamada volta {"erro":"timeout"}.

Jogadas

Uma mensagem JSON por linha, no TCP. O mesmo JSON vai no datagrama multicast.

{"Numero":0,"Jogada":4,"Tabuleiro":[0,0,0,0,1,0,0,0,0],"Resultado":"jog"}
CampoSignificado
Numeroíndice da jogada, começa em 0 e sobe uma unidade por lance válido
Jogadacasa 0 a 8, linha a linha
Tabuleiro0 vazio, 1 = X (quem inicia), 2 = O
Resultadojog, vit, der ou emp

Casas:

0 | 1 | 2
3 | 4 | 5
6 | 7 | 8

Número errado, casa ocupada, tabuleiro que não fecha com a jogada, ou vitória/empate anunciado cedo: o módulo devolve a mesma linha, sem avançar o número, e avisa quem está no teclado. O oponente joga outra casa com o mesmo Numero.

Quem recebe a jogada confere vitória e empate no tabuleiro local. Se perdeu, avisa o humano e manda uma última mensagem com Resultado: "der". No empate, devolve a mesma mensagem com "emp". Aí os dois fecham o socket. Sessenta segundos sem resposta também encerra a partida.

Display

Entra no grupo multicast e imprime o tabuleiro. Pode haver vários, no mesmo grupo e na mesma porta. Cada jogador publica só a jogada que ele mesmo faz. Se um datagrama antigo chegar depois, o display não volta o tabuleiro: o lance de número maior já inclui aquela casa.
